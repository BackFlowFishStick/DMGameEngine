# PB-04 缺陷修复

> 原则：**先复现，再定位，后修复**；修复必须带回回归测试（R10）。

## 步骤

### 1. 立项
- 在 `TASKS.md` 追加条目：现象一句话 + 复现路径 + 崩溃/错误日志关键行。
- 已有他人 🚧 认领同一现象的，不要并行修——联系或等待。

### 2. 复现
- 能用单测复现的优先单测（纯逻辑 bug 一律如此）。
- 渲染类 bug：写最小复现步骤进 TASKS.md 条目（哪个 exe、哪个操作、哪个后端、Validation Layer 输出）。
- 先查 `kb/KB-07-已知问题与陷阱清单.md` 和 `documents/VULKAN_FIXES.md`——也许已经修过类似的。

### 3. 定位
- 引擎有自研 Profiler（F1 面板）与日志系统，先用它们，不要一上来 printf。
- DLL 边界类崩溃（LNK2019 / C4251 / 跨 DLL 传容器崩溃）直接读 kb/KB-02，大概率命中已知模式。

### 4. 修复
- 修复范围最小化；顺手看到的其他问题记 TASKS.md，不夹带（R8）。
- 修复前**先写一个会失败的测试**；修复后它转绿并留在测试套里。

### 5. 收尾
- 若是 Vulkan 正确性类，更新 `documents/VULKAN_FIXES.md` 追加一条修复记录（格式照现有条目）。
- KB-07 沉淀"如何发现这类 bug"的模式；PB-08 自检；TASKS.md ✅。

## 特例：崩溃但无法稳定复现
- 记录全部已知触发条件到 TASKS.md，标记 `🔍 需要更多信息`，不要盲目改代码"试试看"。
- 疑似 GPU 驱动/环境问题的，在条目里注明机器环境（GPU 型号、驱动版本、SDK 版本）。
