# PB-07 分支管理与合并集成（集成管理员）

> 集成管理员是 develop 合并队列的唯一操作者（可由人类兼任）。Agent 的日常 Git 行为见 AGENTS.md §5.2，本手册只讲集成侧。

## 日常合并流程

1. **收集**：确认待合并分支已满足——TASKS.md 状态 `👀 待 review`、提交者跑完 PB-08 自检并在 TASKS.md 备注自检结果。
2. **Review 要点**（快速门禁，10 分钟内）：
   - `git diff origin/develop...branch --stat`：改动范围是否与认领任务一致（夹带 = 退回）。
   - 公共头变更：`DMGE_API` / `DMGameEngine.h` / STL 导出红线（R1）。
   - CMakeLists：新文件已注册（R2）。
   - 测试：新增功能有测试，`ctest` 在管理员机器上复跑全绿。
3. **合并**：
   ```bash
   git checkout develop && git pull
   git merge --no-ff agent/<名字>/<主题>
   # 冲突时：优先拉当事 Agent 对齐语义，管理员不擅自决定跨区域语义
   ctest --test-dir cmake-build-debug --output-on-failure   # 合并后再跑一次
   git push origin develop
   ```
4. **记账与对账**：TASKS.md 标 ✅ + 合并 commit hash；**对账看板**——各 Agent 报告中新发现/建议的任务是否已进待认领区（AGENTS.md §7.5 报告回写义务，漏登即补），进行中条目与实际合并状态一致；通知文档 Agent 有新变更可转写。

## 冲突预防（比解决便宜）

- 公共头（`DMGameEngine.h`、`Components.h`、`CMakeLists.txt`）是热点文件：管理员发现两个进行中分支都改同一热点时，**主动调度先后**——让先合者尽早合入 develop，让后者 rebase，避免长期分叉。
- 文档类文件（kb/KB-07、ENGINE_SUMMARY.md）天然追加冲突：规则是**永远追加到末尾**，rebase 时机械解决即可。

## 异常处理

- **分支烂尾**（Agent 中止且 2 周无进展）：通知所有者后归档——分支不删，TASKS.md 条目改 `⬜` 并注明"半成品在分支 xxx，接手前先读其 commit"。
- **合并后主干坏**：立即 `git revert -m 1 <merge-commit>`（不 force-push、不 rebase develop），原始分支修好后重新走流程；坏因记 KB-07。
- **develop 落后 main 太多**：仅当所有者要求时执行 `git checkout main && git merge --no-ff develop`（发版动作），平时不动 main。

## 禁区

- 禁止 force-push develop/main；禁止 rebase 已 push 的 develop；禁止合并自检未过的分支（"先合了再说"是事故之源）。
