# PB-01 新增引擎子系统（物理 / 音频 / 脚本 / Job System 等）

> 参考先例：Asset 系统（1a）、ECS（1b）、光照（阶段 A+B）——它们的落地方式就是本手册的原型。
> 对应路线图：ENGINE_ROADMAP.md §5（3a~3d）。

## 前置检查

1. 查 `TASKS.md`：该子系统未被认领；查 `documents/ENGINE_SUMMARY.md`：该子系统未存在。
2. 读 `kb/KB-02-DLL边界与STL.md` 和 `kb/KB-01-构建系统.md` —— 子系统 80% 的返工发生在这两处。
3. 确认依赖满足（见 ROADMAP 依赖矩阵）：物理/脚本依赖 1b ECS，音频/Job System 依赖 1a AssetManager。

## 步骤

### 1. 选型与开关
- 第三方库放 `engine/dependencies/<lib>/`；优先单头/无依赖库（项目先例：miniaudio 优于 OpenAL）。
- CMake：在 `engine/CMakeLists.txt` 加编译开关 `DMGE_<MODULE>`（默认 OFF 直到能用），`option()` + `add_subdirectory`/源码引入。**不要**无条件编入。

### 2. 目录骨架
- `engine/src/DMGameEngine/<Module>/`，至少包含：对 API 头（如 `PhysicsWorld.h`）、子系统门面（如 `Physics.h`）。
- 对外门面加进 `src/DMGameEngine.h`（R9），导出符号用 `DMGE_API`。
- **所有新 .cpp/.h 立刻注册进 `engine/CMakeLists.txt` 的显式源文件列表**（R2）。

### 3. ECS 对接（若子系统挂场景）
- 数据放 Component（R4），如 `RigidbodyComponent`；逻辑放 `<Module>System`。
- Component 结构体加进 `Scene/Components.h`，并同步 `SceneSerializer`（见 PB-02 第 5 步）与编辑器 Inspector（告知编辑器 Agent 或按 PB-05 自行添加）。

### 4. 与主循环集成
- System 通过 `Scene` 的 System 列表注册（先例：TransformSystem/MeshRenderSystem/LightSystem）。
- 需要固定步长的（物理）用 accumulator 模式——先例预留见 ENGINE_REVIEW.md D 节。

### 5. 测试
- 至少一组"纯逻辑"单测进 `engine/tests/`（不依赖 GPU/窗口，先例：RenderQueue 排序键、Material uniform 包）。
- 修编译开关 OFF 时全工程仍能构建（`-DDMGE_<MODULE>=OFF` 跑一遍）。

### 6. 收尾
- 跑 PB-08 收尾自检清单。
- 新坑记 kb/KB-07；变更日志进 ENGINE_SUMMARY.md；TASKS.md 标 ✅。
- 在 ENGINE_ROADMAP.md 对应条目标记落地状态（此项文档 Agent 也会做，你只做一行状态标注，详细转写交给文档 Agent）。

## 明确不做
- 不在子系统分支里顺手重构别的模块（发现问题时记 TASKS.md 新条目）。
- 不引入需要复杂构建自定义步骤的第三方库，除非 playbook 评审后更新本节。
