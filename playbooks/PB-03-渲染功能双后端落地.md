# PB-03 渲染功能双后端落地

> 背景：OpenGL 为默认后端、Vulkan 1.3 为可选后端（`-DDMGE_VULKAN_BACKEND=ON`），`Renderer::SetAPI` 运行时切换。
> 已知架构债：OpenGL-first 渗漏（E1，见 `documents/ENGINE_REVIEW.md`）；Vulkan 正确性 A-F 与性能 P0-P3 见 `documents/VulkanBackendReview.md`。

## 核心原则

1. **先想清楚两层**：后端无关的抽象层（Renderer/RenderCommand 语义）与后端实现层。公共接口里禁止出现任何单后端概念（R5）。
2. 动手前读 `kb/KB-03-渲染双后端注意事项.md`——Y 翻转、GLSL 限制、帧内延迟销毁等坑都列在里面。
3. 路线图明示的收敛方向（2b）：SPIR-V 反射取代 regex+手算 std140、`RenderPassDesc` 统一、资源屏障抽象。你的新功能**尽量往这个方向设计**，别加深渗漏。

## 步骤

### 1. 抽象先行
- 在公共头（如 `RendererAPI.h` / 对应资源头）定义接口与描述结构（描述结构体优先于散参数，先例：`RendererAPIInitConfig` 模板方法）。
- 写下两个后端各自如何实现该语义的一段注释/设计说明（写不出来的 = 抽象有问题，回去重设计）。

### 2. OpenGL 实现先行（默认后端，验证语义）
- 实现 + 用 game/editor 跑通视觉验证。

### 3. Vulkan 实现跟进
- 启用方式与 GLSL 限制（显式 in/out、无 sampler 数组、Shutdown 前必须释放 GPU 资源）见 `documents/VULKAN_BACKEND.md`。
- 涉及 per-frame 生命周期的资源必须走延迟销毁路径（0a-B），不得析构即 vkDestroy。

### 4. 验证矩阵
- 两后端 × （game exe + editor exe）都要跑一遍；Vulkan 打开 Validation Layer。
- 切换测试：运行时 `SetAPI` 切换后功能仍正确（先例：D2 API 切换）。

### 5. 测试与收尾
- 纯逻辑部分（排序键、描述结构、状态机）进单测；GPU 行为至少跑运行时冒烟。
- 修改了 `BeginRenderPass`/FrameBuffer 语义的，确认离屏多 pass RTT 路径（editor viewport）不回归。
- PB-08 自检；坑记 KB-03 或 KB-07；变更日志；TASKS.md ✅。

## 明确不做
- 不在渲染分支里改 ECS/Scene 语义；接口需求以 ISSUE 形式记 TASKS.md 找场景 Agent 对齐。
- 不为了"先跑起来"在公共接口加 `#ifdef DMGE_VULKAN_BACKEND` 分支——后端差异只允许存在于实现文件内部。
