# PB-06 人类向文档撰写（文档 Agent 专属）

> 定位：documents/ 里现有 17 篇是**工程档案**（设计决策、评审、踩坑实录），面向"参与开发的人"。
> 本手册定义的产出是**人类向文档**：让一个新读者（人类学习者、面试官、未来的自己）能读懂这个引擎、上手这个项目。

## 目录约定

- 人类向文档统一放 `documents/guide/`，由文档 Agent 创建并维护 `documents/guide/README.md` 索引。
- 工程档案（documents/ 根下的既有文件）**只增不毁**；发现过时内容，在文件顶部加"⚠️ 状态更新"注记并指向新事实，不重写历史档案。
- Agent 向资料（`kb/`、`playbooks/`）文档 Agent 负责质量维护：条目格式统一、去重、过期条目归档。

## 文档 Agent 的常规工作循环

1. **跟随集成**：每次 develop 有合并（`git log` 观察），从 ENGINE_SUMMARY.md 增量条目提炼"阶段进展"，更新 `documents/guide/` 对应章节——这是防止文档与代码脱节的主通道。
2. **补齐图谱**：按下表检查 guide 目录完整性，缺什么补什么（一次只写一篇，写完再下一篇）。

| 优先级 | 文档 | 素材来源 |
|---|---|---|
| P0 | GettingStarted.md（克隆→构建→跑 game/editor→跑测试） | kb/KB-01、PRECOMPILED_HEADER.md、实际操作验证 |
| P0 | ArchitectureOverview.md（模块图 + 数据流：一帧的生命周期） | ENGINE_SUMMARY.md、ECS_DESIGN.md |
| P1 | 各子系统 Tour（渲染/资产/场景序列化/编辑器，每篇一篇） | 对应 *_DESIGN.md、*_CONCEPTS.md |
| P1 | 学习路线图（"如果你要读懂这份代码，按什么顺序读"） | ENGINE_ROADMAP.md、代码结构 |
| P2 | 术语表（DMGE_API、AssetHandle、System、RenderPass…） | ASSET_UUID_CONCEPTS.md、ECS_CONCEPTS.md |

3. **写作规范**：
   - 中文为主；代码、类型名保留原文。
   - 每个"是什么"尽量配"在哪里"（`engine/src/DMGameEngine/...` 具体路径），让读者能跳转验证。
   - 图示用 mermaid（模块图/流程图）或 ASCII，保持 markdown 纯文本可 diff。
   - 写完**必须对照代码核验**每个路径/类名/函数名存在且行为如所述（文档 Agent 的可信度就靠这一条）。
4. **Git 行为**：小幅更新（状态注记、索引、单篇补充）直接提交 develop，commit 前缀 `docs:`；结构性的新增/重排开 `docs/<主题>` 分支（见 AGENTS.md §5.4）。

## 明确不做

- 不改代码（发现代码问题记 TASKS.md）。
- 不复制粘贴工程档案充数——guide 是**转述与提炼**，链接到档案而不是重写档案。
- 不写空泛建筑学散文；每篇 guide 的验收标准是"新人按它操作能跑通/读懂"。
