# KB-01 构建系统与预编译头

> 深度阅读：`documents/PRECOMPILED_HEADER.md`（原理+排错）、`documents/ENGINE_SUMMARY.md` 构建系统章节。

## 构建事实

- CMake ≥ 3.20，C++23，MSVC（VS 工具链），`/W4 /utf-8`。
- 根 CMakeLists 聚合三个 target：`engine`（DLL）+ `game` + `editor`。
- **源文件显式列出，禁 GLOB**：新增 .cpp/.h 必须手动加进对应 CMakeLists 的 `set(DMGE_SOURCES ...)`。忘注册的症状是 LNK2019/行为像没编译——先查这里。
- 首选 CLion 内置 Ninja 工具链构建；裸终端 cmake 常报 LNK1104（缺 VS 环境），不是代码问题。
- 依赖位置：`engine/dependencies/`、`editor/dependencies/`；GoogleTest 走 FetchContent（`DMGE_BUILD_TESTS=ON`）。
- 测试 target `dmge_tests` 的 POST_BUILD 会拷引擎 DLL 到测试目录——测试 exe 直接跑即可，不要手动搬 DLL。
- Vulkan 后端：`-DDMGE_VULKAN_BACKEND=ON`，需本机装 Vulkan SDK（VMA + shaderc）。

## 预编译头（PCH）规则

- `dmge_pch.h` **只允许** stdlib + glm + spdlog。塞项目头 = 任何头改动全量重编，且引发依赖地狱。
- `target_precompile_headers(... PRIVATE ...)` + CXX 守卫；`DMGE_USE_PCH` 可关（排错时先关 PCH 复试）。
- **测试 target 不复用引擎 PCH**（双 glm 实例冲突，先例事故）。
- 若头文件用 `#pragma once` 且被 PCH 与普通编译两种路径包含出现行为差异，先怀疑 PCH 缓存：删 `cmake-build-debug` 重建再判断。

## 常见症状速查

| 症状 | 首查 |
|---|---|
| LNK1104 打不开 .lib/.dll | 构建环境（CLion/Ninja vs 裸终端），不是代码 |
| LNK2019 消费者 exe 引用引擎符号未解析 | 符号没 `DMGE_API` 导出，或模板/STL 未显式实例化（见 KB-02） |
| 新文件"不存在" | 忘注册 CMakeLists（GLOB 时代后遗症已清除，别再犯） |
| 改了头但行为没变 | PCH 缓存，重建 |
