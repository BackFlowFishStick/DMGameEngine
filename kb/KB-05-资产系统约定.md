# KB-05 资产系统约定

> 深度阅读：`documents/ASSET_DESIGN.md`（设计）、`documents/ASSET_UUID_CONCEPTS.md`（UUID 体系）、`documents/MATERIAL_OVERRIDE_SERIALIZATION.md`。

## 核心设计：身份与路径分离

- **AssetHandle 只存 uint64 UUID**，是纯粹的身份令牌——不持指针、不持路径。
- AssetManager 内部三表：UUID→注册表项 / 路径→UUID / UUID→weak_ptr 缓存（去重）。
- 场景文件里资产引用一律写 UUID；路径只在导入/注册时出现一次。

## 使用规则

1. 任何需要"引用某资产"的地方（组件、序列化、编辑器拖拽）用 `AssetHandle`，**禁止**存文件路径字符串或裸 `Ref<>`（后者会绕过去重缓存并破坏生命周期管理）。
2. 加载走 `AssetManager::Load<T>(uuid/path)`；新资产类型需要写 `AssetLoader<T>` 特化——**跨 DLL 消费者直接用模板特化会 LNK2019**（只有 `Mesh` 已导出特化），消费者 exe 要么走 DLL 内门面接口，要么把特化显式实例化并导出（先例见 Mesh 的 `DMGE_API`）。
3. GPU 资源生命周期：`Ref` 归零 ≠ 可立即释放（帧在飞），需延迟释放队列对齐 Vulkan 0a-B 的 deletion queue——新增 GPU 持有型资产类型时必须考虑这一点。

## 导入器现状（assimp，2026-08-01 引入）

- 支持 `.fbx/.obj/.gltf/.glb` → `Mesh`（节点烘焙、超集顶点布局、`.mat` 材质映射）。
- 已知局限（动手前确认没被绕开）：
  - 仅**静态网格**：无骨骼/动画/形变目标。
  - **同步加载**：无异步/后台解码（计划挂 3d Job System）。
  - 材质仅外部 `.mat` 查找：不自动生成材质、不绑纹理（`Material` 尚无纹理绑定）。
  - UV 按 GL 翻转假定，未用 `FlipUVs`。
- 材质格式 `.mat`（含纹理槽位定义），格式细节见 ASSET_DESIGN.md。
