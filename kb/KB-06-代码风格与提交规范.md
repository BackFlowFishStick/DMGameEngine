# KB-06 代码风格与提交规范

> 本条是全项目一致性基线。PR review 时风格不一致直接退回，不争论。

## 代码风格

- 命名空间：引擎公共代码 `namespace DMGameEngine`（内部实现可用子命名空间）；智能指针统一 `DM::Ref<T>` / `DM::Scope<T>`（`DMGameEngine.h` 定义），**禁止散写** `std::shared_ptr`/`unique_ptr` 拼写。
- 类成员 `m_PascalCase`；类型 `PascalCase`；函数 `PascalCase`（先例：`Renderer::Submit`、`AssetManager::Load`）；局部变量 camelCase。
- 日志：走引擎日志宏（spdlog 封装 `DMGE_LOG_*`），禁止 printf/cout。
- 断言：引擎内部用 `DMGE_ASSERT`/`DMGE_CORE_ASSERT` 系列（先例见现有代码），release 语义注意与 `VK_CHECK` 的 D 项教训（release 不能静默 no-op）。
- 文件：UTF-8 **无 BOM**；头文件 `#pragma once`；一个公共类一个头（与现有布局一致）。
- 注释：只解释"为什么/约束"，不复述代码；公开 API 头给一行用途说明即可。

## C++ 纪律

- C++23，可用特性按现有代码已使用为准（不要为了新而新）。
- 值语义优先；裸 new/delete 禁止（用 DM::Scope/Ref 或栈对象）。
- 单例仅限既有先例模式（Application/AssetManager 风格），新增单例要在设计说明里给理由。

## Commit 规范（与 git 历史一致）

```
<type>(<scope>): 中文描述
feat(engine): xxx    fix(editor): xxx    refactor/renderer: xxx
docs(kb): xxx        test: xxx           chore: xxx
```

- 每个 commit 可编译、ctest 通过（bisect 友好）。
- scope 用模块名（engine/editor/game/renderer/scene/asset/kb/docs…）。
- 不夹带：格式化全文件、无关重构、构建产物一律不进 commit。

## 文档写作

- 全部 markdown 中文（代码/类型名保留原文）。
- 工程档案在 `documents/`（只增不毁，状态注记不重写）；人类向 guide 在 `documents/guide/`；Agent 资料在 `kb/`、`playbooks/`。
